# Testing — การทดสอบ

## ระดับการทดสอบ

### ตรวจเอกสารและโค้ด

- ตรวจโครงสร้างไฟล์ กฎฐานข้อมูล จุดเรียก API และสัญญาข้อมูล
- ตรวจว่าไม่มีการใช้ข้อมูลจองเป็นผู้กำหนดรหัสไลน์คนขับ

### ทดสอบพฤติกรรม

- ไม่เข้าสู่ระบบอ่าน/เขียนไม่ได้
- ผู้ใช้คนอื่นอ่านของเจ้าของไม่ได้
- เจ้าของและผู้ดูแลได้สิทธิ์ตามบทบาท
- ปฏิเสธราคา จำนวนคน สถานะ และข้อมูลรูปแบบผิด
- ป้องกันรหัสรายการซ้ำ การส่งซ้ำ และการใช้รหัสรายการของผู้อื่น
- ป้องกันข้อมูลแทรกโค้ดและการส่งรหัสผู้รับปลอม

### ทดสอบโหลด

- ใช้ Firebase Emulator หรือระบบทดสอบเท่านั้น
- ใช้ข้อมูลจำลอง โหมดทดสอบ และล้างข้อมูลหลังจบ
- ขอบเขตที่อนุมัติ: สูงสุด 100 ผู้ใช้งานพร้อมกัน และจำลองจองพร้อมกัน 20 คน
- ห้ามยิงระบบจริงแบบเร่งโหลดหรือทดสอบกระแทก

## หลักฐานล่าสุด

- ชุดตรวจบน GitHub ผ่านบนกิ่ง `security/vehicle-line-binding`
- ระบบจำลอง: ผู้ใช้งานสูงสุด 100 คน อ่านพร้อมกัน 80 คน จองพร้อมกัน 20 คน
- การตรวจสอบ 22,766 ครั้งผ่านทั้งหมด และคำขอ 22,727 ครั้งไม่ล้มเหลว
- ค่าความเร็วร้อยละ 95 ที่รายงานคือประมาณ 22.28 มิลลิวินาที
- ค่าร้อยละ 99 ผ่านเกณฑ์ต่ำกว่า 2 วินาที แต่ผลที่เก็บไว้ไม่ได้แสดงค่าตัวเลขละเอียด
- ยังไม่มีการทดสอบโหลดบนระบบจริง

## คำสั่งตรวจหลัก

- `node --test tests/*.test.js`
- `firebase emulators:exec --only auth,database,functions,storage --project sl-transit-9464e "node tools/run-emulator-validation.js"`
- ชุดโหลดอยู่ที่ `tests/k6/booking-concurrency-emulator.js`

## เกณฑ์ไม่ให้รายงานผ่าน

- มีช่องโหว่ระดับร้ายแรงหรือสูงที่ยังไม่แก้
- ยังยืนยันไม่ได้ว่าเซิร์ฟเวอร์เป็นผู้ตัดสินราคาและสถานะสำคัญ
- มีการอ่านหรือเขียนโดยไม่ผ่านสิทธิ์
- ใช้ระบบจริงในการทดสอบโหลด
- ไม่มีหลักฐานว่าล้างข้อมูลจำลองและไม่มีการส่งไลน์จริงในชุดจำลอง
