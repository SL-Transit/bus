# Implementation Plan — แผนลงมือทำ

## ขั้นที่ 1: อ่านและล็อกขอบเขต

- อ่านเอกสารชุดนี้และ `ai-handoffs/WORK-STATUS.md`
- ตรวจว่าพื้นที่ที่ต้องแก้ไม่มี AI อื่นกำลังทำอยู่
- ระบุไฟล์และเส้นทางข้อมูลที่กระทบให้ชัด

## ขั้นที่ 2: เขียนข้อกำหนดงาน

- เขียนพฤติกรรมที่ต้องได้
- เขียนสิ่งที่ห้ามเปลี่ยน
- ระบุข้อมูลส่วนตัวและผลกระทบระบบจริง
- กำหนดหลักฐานที่จะใช้ตัดสินว่าผ่าน

## ขั้นที่ 3: ตรวจสัญญาเดิม

- อ่านโค้ดและกฎก่อนออกแบบของใหม่
- แยกข้อมูลที่ยืนยันแล้วออกจากข้อมูลเสนอและข้อมูลยังไม่ยืนยัน
- ตรวจ API, สิทธิ์, การคำนวณ, การเขียนข้อมูล และการแจ้งเตือน

## ขั้นที่ 4: ออกแบบการเปลี่ยนแปลง

- ใช้ศูนย์กลางเดิมก่อนสร้างเส้นทางใหม่
- ห้ามให้หน้าจอเป็นแหล่งตัดสินใจด้านราคา สิทธิ์ หรือผู้รับแจ้งเตือน
- กำหนดการย้อนกลับและการปิดใช้งานกรณีผิดพลาด

## ขั้นที่ 5: ลงมืออย่างจำกัดขอบเขต

- แก้เฉพาะไฟล์ที่ระบุในข้อกำหนด
- เพิ่มการทดสอบพฤติกรรม ไม่ใช้การค้นข้อความในไฟล์เพียงอย่างเดียว
- ไม่เขียน Firebase จริงและไม่ส่งข้อความจริง เว้นแต่มีอนุมัติเฉพาะกิจ

## ขั้นที่ 6: ตรวจทาน

- รันชุดทดสอบเดิมและชุดใหม่
- ตรวจความปลอดภัยและข้อมูลส่วนตัว
- ตรวจผลกระทบกับหน้าและฟังก์ชันที่เกี่ยวข้อง
- ตรวจ GitHub Actions, GitHub Pages และสถานะเผยแพร่ถ้ามีการส่งงาน

## ขั้นที่ 7: ส่งมอบ

- รายงานไฟล์ที่แก้ การทดสอบ ผลกระทบ และสิ่งที่ยังค้าง
- ระบุชัดว่าอะไรเป็นการทดสอบระบบจำลองและอะไรเป็นระบบจริง
- ขออนุมัติแยกก่อนรวมงานหรือเผยแพร่สิ่งที่กระทบระบบจริง
