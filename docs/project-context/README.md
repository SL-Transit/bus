# SL-Transit Project Context

สถานะเอกสาร: ฉบับจัดระเบียบจากโค้ดและเอกสารบน `main`

เอกสารชุดนี้เป็นจุดเริ่มต้นกลางสำหรับการทำงานกับโครงการ SL-Transit ทุกครั้ง ก่อนแก้ไขงานใดให้เริ่มอ่านตามลำดับนี้:

1. `01-REQUIREMENTS.md` — สิ่งที่โครงการต้องทำและขอบเขตที่ห้ามข้าม
2. `02-ARCHITECTURE.md` — โครงสร้างระบบและหน้าที่ของแต่ละส่วน
3. `03-BUSINESS-RULES.md` — กติกาทางธุรกิจและความปลอดภัย
4. `04-API-SPECIFICATION.md` — ช่องทางเชื่อมต่อและข้อมูลที่รับส่ง
5. `05-DECISIONS.md` — มติที่ยืนยันแล้วและเรื่องที่ยังรออนุมัติ
6. `06-TESTING.md` — วิธีตรวจสอบและเกณฑ์ผ่าน
7. `07-IMPLEMENTATION-PLAN.md` — ขั้นตอนทำงานก่อนลงมือ
8. `08-REVIEW-CHECKLIST.md` — รายการตรวจทานก่อนส่งมอบ

## สถานะข้อมูล

- **ยืนยันแล้ว**: มีหลักฐานจากโค้ด กฎฐานข้อมูล หรือการทดสอบ/การเผยแพร่ที่ระบุไว้ชัดเจน
- **เสนอ**: มีโครงสร้างรองรับ แต่ยังต้องให้เจ้าของยืนยันความหมายหรือกติกา
- **ยังไม่ยืนยัน**: ห้ามนำไปคำนวณ แสดงเป็นตัวเลขจริง หรือใช้ตัดสินใจทางธุรกิจ
- **ถูกระงับ**: ห้ามทำจนกว่าจะมีข้อมูล สิทธิ์ ระบบจำลอง หรือการอนุมัติเพิ่ม

## กติกาการทำงาน

- อ่าน `ai-handoffs/WORK-STATUS.md` ก่อนแก้ไฟล์ทุกครั้ง
- ตรวจว่ามี AI อื่นกำลังทำงานในไฟล์หรือพื้นที่เดียวกันหรือไม่
- GitHub `main` เป็นแหล่งอ้างอิงหลักของโค้ด
- ห้ามเขียนฐานข้อมูลจริง ห้ามส่งข้อความจริง และห้ามเผยแพร่ระบบจริงโดยไม่มีการอนุมัติเฉพาะงาน
- ห้ามนำข้อมูลผู้โดยสารเต็ม เบอร์โทรเต็ม รหัสไลน์เต็ม หรือโทเคนมาใส่ในรายงานและผลทดสอบ
- งานหนึ่งรอบต้องเดินตามลำดับ: ข้อกำหนด → บริบท → แผน → ลงมือ → ตรวจทาน → รายงาน

เอกสารอ้างอิงเดิม: `ai-handoffs/START-HERE-FOR-ALL-AIS.md`, `ai-handoffs/MAIN-AI-DASHBOARD.md`, `ai-handoffs/WORK-STATUS.md`, `ai-handoffs/CENTRAL-REPORT.md` และ `ai-handoffs/COORDINATION-RULES.md`
